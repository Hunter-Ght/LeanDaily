# 饮食照片识别

实现位于 `lib/data/vision.dart` 与 `lib/ui/sheets/meal_sheet.dart`。识别使用用户自己配置的服务，发送照片前沿用 AI 数据授权检查。提示词改进尚未经过真实模型餐图对照，自动测试只能确认请求、结果处理与存储口径。

## 估算规则

- 多张照片是同一餐的不同角度，菜品与原料不能重复计数。
- 优先采用用户提供的克数、个人份额及清晰的包装标示；区分生重／熟重、每份／每 100 g。
- 共享菜不默认计入整桌；用油与酱汁计入菜品，无法确认的份量和成分写进估算说明。
- 只拍吃前时估算个人份额的整份，用户可对整餐或单项选择 ¼／½／¾／全部。重复调整以识别原始份量为基准；手动修改单项后，以修改后的数值为该项新基准。
- 吃前吃后逐项匹配，只计算实际吃下的量。画面中消失不等于吃光；无法匹配或无法判断个人份额时退回吃前估算。
- 无食物时返回空列表，界面说明未识别出食物；summary 只说明估算依据，不评价饮食好坏。模型 confidence 不在界面作为准确率展示。

## 结果口径

模型响应继续使用 `items`、`summary`、`confidence`、`warning`。食物项为 `name`、`portion`、`kcal`、`protein`、`carbs`、`fat`。

| 模型 basis | 保存的 basis | 结果含义 |
| --- | --- | --- |
| `before_only` | `仅吃前估算` | 只拍吃前或前后无法对应，需要用户确认份量 |
| `compare` | `前后对比` | 前后能够对应，数值为逐项估算的实际摄入 |

有餐后照片的响应必须明确返回合法 basis；缺失或值错误时拒绝作为成功结果。仅对实际采用 `compare` 的结果接受 0～1 的 `eaten_ratio`。旧记录不迁移。

餐卡“我吃光了”只更新现有 `after_skipped` 字段，保留记录 ID、食物明细、营养与照片；不重新识别。份量已经调整过的记录仍保留当前营养数值。

## 真实模型验证清单

正式评估时固定模型、请求参数和同一组图片，保留用户已知的克数、包装标签及个人份额作为参考。分别跑修改前后提示词，记录食物遗漏／重复、个人份额、生熟口径、营养估算误差、降级原因与 JSON 成功率；不能用模型自评 confidence 替代这些检查。

| 场景 | 重点核对 |
| --- | --- |
| 单人米饭与肉菜、多角度 | 不重复计数，分别估算菜和主食 |
| 包装食品／无糖饮料 | 可读标签优先，不编造看不清的营养数字 |
| 多人共享餐 | 不把整桌当作个人摄入，个人份额不明时提示确认 |
| 餐后各菜剩余不同 | 逐项计算，不能全餐统一折算 |
| 餐后盘子移出画面／被遮挡 | 不直接认定吃光，必要时降级 |
| 前后不同餐 | 返回 `before_only` 并解释原因 |
| 汤、酱汁、油脂 | 明确估算假设，避免重复加油 |
| 没有食物的照片 | 空 items，允许用户手动记录 |

自动回归在 `test/data_services_test.dart`、`test/meal_sheet_test.dart` 与 `test/log_meal_actions_test.dart`，均使用 FakeNative，不会发送照片到外部服务。
