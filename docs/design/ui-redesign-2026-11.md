# 2026-11 界面改版规范：身体为主角的活力极简

用户已确认方向。设计稿（单文件网页，含首页、训练中、器械详情、记录、进度、规范）：
`out/design/2026-11-05-设计方向稿.html`（本机文件，不进仓库）。

## 一、原则

1. **人体是主线**：首页看「今天要练」、记录看「那天练了」、进度看「几周累计」、器械看「主练/辅助」，统一用 `lib/ui/kit/body_figure.dart` 的 `BodyFigure`。
2. **颜色有含义**（`lib/theme/tokens.dart`）：
   - `tint` 发力橙：只用于**训练动作**的主按钮（开始训练、完成一组、记录这个动作）、发力/今天练的肌肉、进度条、连续天数。
   - `recover` / `recoverSoft` 恢复青：可以练、已恢复、恢复中、完成勾。
   - `primary` / `onPrimary` 墨色：**非训练**的主操作（记体重、保存、开始评估、底部加号等）。
   - `protein` / `kcal`：只用于饮食数据，小面积。
   - 颜色一律取 `context.pal`，`bash tool/lint_tokens.sh` 必须通过。
3. **按钮只有三级**：主（`SheetButton(primary: true)` 发力橙，或 `ink: true` 墨色）/ 次（`soft: true`）/ 文字链接。**每屏最多一个主按钮**。
4. **数字是主角**：组数、重量、次数、天数、体重、热量用 `AppText.num(p, size)`（Numeral 字体、等宽数字），做大；单位用小号正文字。
5. **少卡片、少灰字**：靠字号、留白、对齐分组，不必每块都套卡片；去掉整行「a · b · c · d」式的灰色元信息堆叠；解释性长文默认收起（点「?」或「说明」再展开）。
6. **标题层级**：页面主标题 `AppText.display`（30–34），区块标题 `AppText.title`（20），正文 16–17，注释 13。
7. **动效**：可点元素用 `Pressable`（已有按压回弹）；状态切换用现有转场（`PushSwitcher`、`Reveal` 等）；尊重 `MediaQuery.disableAnimationsOf`。
8. **两种模式**：生活页面跟随系统亮/暗；**训练中**（训练模式 + 组间休息）固定深色、大读数、主要按钮在下半屏。
9. 底部导航：选中项不用橙色色块，改为颜色变深 + 小橙点（由负责「我的/导航」的改动统一处理，其他页面不要动导航）。

## 二、各页面要点

- **首页**（`lib/ui/today/`）：顶部日期 + 连续天数；大标题「今天练 / 胸 · 背 · 腹」（部位用发力橙）；一行三个大数字（动作数、分钟、组数）；`BodyFigure` 今天练的肌肉 effort+breathe、恢复中的 recover，下方图例；唯一橙色主按钮「开始训练/继续训练」；今日动作列表（缩略图 + 名称 + 右侧大号「组×次」）；本周圆环 + 蛋白/热量两条进度。休息日、未评估、已完成等状态也要按同一风格。
- **训练中**（`lib/ui/training/`）：固定深色；顶部关闭、动作名、计时；分段组进度条；3D 示范；重量/次数大读数（56–64 号 Numeral）+ 大加减按钮；上一组参考；底部大号橙色「完成第 N 组」。组间休息：全屏倒计时大圆环、+30 秒 / 跳过、下一组与下一个动作预告。
- **记录页**（`lib/ui/log/`）：标题为日期；一周日期条（选中为墨色块，橙点=训练、黄点=蛋白达标），月历收为按钮；当天三项小结（训练组数、蛋白、热量）；**饮食与训练合并为一条按时间排序的时间线**：训练块带小 `BodyFigure` 和每个动作平铺的组数片，饮食块显示餐名、内容和热量/三大营养素；所有新增入口收进右下角墨色加号。
- **进度页**（`lib/ui/stats/`）：标题「进度」+ 时间范围；近 4 周累计热力 `BodyFigure(heat:)` + 「练得少—练得多」图例；一条具体建议（练得最少的部位 + 可用动作，可复用 `lib/domain/free_training.dart`）；体重大数字 + 趋势线 + 变化量；力量进步（动作最佳 e1RM/重量提升）；坚持格子（近 12 周）。说明文字默认收起。
- **器械详情 / 我的 / 导航**：器械详情按设计稿收尾（主按钮「记录这个动作」橙色，可以练用恢复青标签）；「我的」去掉彩色方块图标，改单色图标与更大的标题；底部导航选中样式按第一节第 9 条。

## 三、协作约定（并行开发）

- 只改自己负责的目录；**不要改** `lib/theme/`、`lib/ui/kit/` 已有文件（可以在自己的目录新增文件）。确需改共用组件时，在汇报里说明，由主线统一改。
- 新增中文界面文字的翻译：**不要**改 `tool/l10n/*.json` 与 `assets/l10n/*.json`；把新文案写进 `tool/l10n/pending/<你的模块>.json`，格式 `{"中文": {"en": "English", "zh_Hant": "繁體"}}`，主线合并时统一导入。因此 `test/localization_test.dart` 允许只因这些待合并文案失败，其他测试必须全部通过。
- 测试：`export PATH="$HOME/.local/share/flutter/bin:$PATH"; TZ=Asia/Shanghai flutter test`；静态检查 `dart analyze lib test`（不要用 flutter analyze）；`bash tool/lint_tokens.sh`。
- 旧测试因界面改版失败时，优先更新测试步骤与断言（保持被测的行为），并在汇报里列出。
- 截图自查：参照 `test/support/harness.dart` 的 `shot()`，设置 `LEANDAILY_TEST_FONT="/System/Library/Fonts/Hiragino Sans GB.ttc"` 与 `LEANDAILY_SHOT_DIR=<你的目录>`，图片需先 `precacheImage`，用 Read 看图；浅色、深色、393×852 与 820×1180 都要看。

## 四、弹层、菜单与表单（第二轮，2026-11-06）

共用组件已经改好（`lib/ui/kit/sheet.dart`、`menu.dart`、`grouped.dart`、`form.dart`），各弹层内容按下面统一：

1. **顶栏**（`AppSheet` 自带）：左「取消」正文色、中间标题、右「保存」墨色胶囊。不要自己再画一套顶栏。
2. **橙色只给训练**：弹层里只有“记录/保存这一组”“开始训练”这类训练动作的主按钮，以及发力数据，才用 `tint`。饮食、设置、身体数据的主按钮用墨色（`SheetButton(ink: true)` 或 `FormButton(filled: true)`）。文字链接（如「设置我的健身房」「调整」）用正文色加粗，可带 `AppIcon('right')` 小箭头，**不要**用橙色字。
3. **选中态**：分段用 `AppSegments`；可多选的小胶囊选中时用墨色底（`p.primary` / `p.onPrimary`），未选中用 `p.fill2` 底 + 正文色；**不要**用 `tintSoft` 橙底当选中。
4. **层级**：区块标题用 `GroupHeader`（已是 15 号粗体正文色），或大区块用 `AppText.title`；说明文字 13–14 号次要色，长说明默认收起。去掉「a · b · c」式的灰色元信息长串，只留一项最有用的信息。
5. **数字**：重量、次数、热量、蛋白、份量这类读数用 `AppText.num`，单位用小号正文字；营养数字可以用 `p.protein` / `p.kcal`，只做小面积点缀。
6. **卡片**：内容卡 `p.card`、圆角 18–22，卡内留白 16；列表行最小高 52；图标块用 `p.fill2` 底 + 正文色图标（训练动作可用 `tintSoft` 底 + `tint` 图标）。
7. **滚动**：弹层内的主滚动区由 `AppSheet` 提供（已修好“滑回顶部先空一大片再弹回”）。不要在弹层里另外加 `BouncingScrollPhysics`；嵌套的竖向滚动区用 `SheetController.of(context).physics` 或 `ClampingScrollPhysics`。底部固定按钮放 `AppSheet.footer`。
8. **菜单/确认**：用 `showActionMenu`（`MenuAction` 支持 `detail` 说明、`group` 分组、`effort` 训练项）与 `showConfirm`，不要自己画菜单。
9. **训练中打开的弹层**会自动沿用深色（不用处理）。

## 五、第三轮补充（2026-11-08）

1. **开关**（`FormSwitch`）打开为墨色，不再是系统绿。新界面不要再用 `p.ok` 绿色做状态色。
2. **恢复状态标签**（`RecoveryTag`）：可以练 = 恢复青底 + 实心青点；恢复中 = 中性 `fill2` 底 + 空心青圈 + 次要色文字。**发力橙不表示“没恢复”。**
3. **空状态**：不要一堆空卡片或一行灰字。整页 / 整块只放一个引导：淡化的 `BodyFigure` 或图标 + 一句正文色说明 + 一个明确的下一步按钮。
4. **图表数据太少**（只有 1 个点）时不画空坐标，改成一句提示和那一个数字。
5. **只格式化自己改过的文件**：`dart format <文件>`，不要 `dart format lib` 或整个仓库。
