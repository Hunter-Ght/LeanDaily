一、准则 2.1(a)：无法设置 AI 识别

改动：
- “设置 AI 连接”直接放在 AI 拍照记录页面，不再需要去“我的 > 备份与高级”里找。
- 选择 OpenAI 后，接口地址和模型自动填好，只需粘贴 API Key。
- 修复了手动填写流程中的报错；粘贴完整接口地址会自动规范化。
- 新增“测试 AI 连接”，会明确提示是 Key 无效、无模型权限还是额度不足。

App Review Information 备注里已提供一个可用、已充值的 OpenAI 审核专用 API Key。我们于 [[日期]] 在 [[设备]]、[[iPadOS 版本]] 上用构建 33 测试过，照片识别成功。

测试步骤（约一分钟）：
1. 记录 > 饮食 > 拍照记饮食。
2. 点“设置 AI 连接” > 服务商 > OpenAI，粘贴备注里的 API Key。
3. 点“测试 AI 连接” > “发送测试请求”，成功后点保存，回到记餐页面。
4. 在“拍下这一餐”下点“相册”，选一张食物照片。
5. 点“AI识别营养”，出现授权页后点“同意并识别”，几秒后出现营养估算，可保存。

二、准则 5.1.1(i) 和 5.1.2(i)：向第三方 AI 服务共享数据

AI 识别是可选功能，默认关闭；手动记餐和所有训练功能都不依赖它。

每次上传照片前，App 都会显示授权页：
- 写明接收方：OpenAI，地址 https://api.openai.com/v1。
- 列出发送内容：所选饮食照片、餐次、补充说明（最多 300 字）、营养估算指令，以及用于认证的 API Key 和设备 IP 地址。
- 写明不发送：身体资料、身体测量和训练记录。
- 附 OpenAI 数据使用政策链接。
- 只有点“同意并识别”才发送；取消不发送；相机/相册授权不视为同意。

旧版本里的授权已作废，所有用户都会重新看到新的授权页。

iOS 上 OpenAI 是唯一的 AI 接收方，无法使用自定义或其他第三方接口，旧的自定义设置也不会被转发到其他服务。请求由设备直接发到 OpenAI，并设置 store=false；我们不运营任何接收这些数据的服务器。

隐私政策（App 内也可查看）现已写明收集哪些数据、如何收集、全部用途、与 OpenAI 共享，并确认 OpenAI 对这些数据提供相同或同等的保护，包括其留存期限和默认不用于训练的条款：
https://hunter-ght.github.io/LeanDaily/privacy/
