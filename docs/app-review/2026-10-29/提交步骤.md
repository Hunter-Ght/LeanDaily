# 这次怎么继续

选择最新版 2.3.7（32），不回退修 2.3.4（25）。上传 TestFlight 不会自动换掉送审构建，必须在 App Store Connect 的待送审版本中重新选择新构建。公开商店版本字段和新包营销版本必须匹配；按后台状态编辑可编辑版本，或创建对应版本，不要继续选 25。

## 程序已处理

- 修复手动服务选择空地址异常、完整推理 URL 重复拼接，以及地址/模型/密钥首尾空格。
- 新增明确同意后才发起的文字连接测试；区分密钥/权限、额度、地址/模型和错误响应。文字成功不是图片能力验证。
- iOS 仅允许 OpenAI 官方 API，拒绝旧自定义/Google Gemini 目的地，不自动移交密钥。Android 保留兼容选择。
- 每次发送照片都先显示接收方、实际服务器、数据、API 认证、IP、留存和条款。取消不发送。更新授权版本，旧授权作废。
- 三语言 App 内和公开隐私政策同步更新。

## 醒来后必须完成的最少操作

1. App Store Connect 私密的 App Review Information 内填入有效、专供审核的 OpenAI API Key、可用的图片输入模型、Responses 协议和官方地址。原来若给的是自定义服务或 Gemini 参数，必须替换。确保 API 已开通账单/额度，允许审核所在地区。不要把 Key 放进回复附件、GitHub、公开视频或代码。不能要求审核员自行购买额度或创建账号。
2. 用该账号先跑“测试 AI 连接”，再真正在 iPad 上识别一张普通食物照片并保存。测试拒绝授权确实不发送；清洁安装和从旧版升级各走一次。先备份重要记录；不要删除有真实数据的 App 来测试。
3. 本机只有 iPadOS 26.3 模拟器，不能替代审核设备 iPad Air M4 / iPadOS 27.0.1。需用对应或兼容最新版真实 iPad 做最后验收；旧 2.1 信息请求若仍要求真机录屏，也要附上同一新构建的视频，遮住 Key。
4. 确认新构建处理完成、公开隐私页显示 2026-10-29 版本，核对 App Privacy 问卷与照片、用户内容、营养/健康、提供商账号关联等实际处理一致。不能因本地存储就直接填“完全不收集”。
5. 保留私密凭据，追加 NOTES_EN.txt 中可用的说明并移除其中“待填凭据”指令；将 REPLY_EN.txt 粘贴到当前审核消息的“回复 App 审核”。只有上述条件已满足才能使用其中“dedicated credentials supplied privately”的表述。不要把 VALIDATION.md 的未执行项写成已通过。
6. 选新构建后重新提交审核。当前没有自动发送回复、填写凭据或重新提交公开审核。

## 为什么还需要有效凭据

只有 baseURL/示例模型不能让 AI 运转，界面修复也不能制造服务商额度。App 不内置共享 Key。助手没有读取你的私密 API Key，也没有使用你的真实照片发起付费请求。这个外部前提未验证，就不能保证苹果不会再次以 2.1 拒绝。

## 数据保护边界

收紧 iOS 服务端点、HTTPS、数据最小化、明确授权和 store=false 是技术措施，不是对第三方“零留存”的保证。OpenAI 默认不训练、滥用监测通常保留最多 30 天且有例外；需接受其实际条款。苹果最终是否认可 BYOK 方案由审核决定，不能靠免责声明替代完整功能或等同保护。
