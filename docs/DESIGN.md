# 设计原则

LeanDaily 的界面遵循苹果的人机界面习惯：大标题、分组列表、弹层、弹簧动画；但目标用户是"想练出线条的人"，所以更强调**一屏一件事**。

## 1. 一屏回答一个问题

- 今日页回答"我现在该练什么"：一个大按钮；其余信息（饮食、本周）降级成细条。
- 记录页优先回答"这一餐怎么记"：从其他标签进入时默认饮食，饮食｜训练切换在手机和宽屏上都保留。主动切到训练后翻日期保持选择；全屏训练保存不改变这个选择，手动补训练保存后显示训练。
- 饮食列表顶部使用一张中性分组卡：首行是拍照记饮食与小 AI 标识，仅相机图标局部用强调色；下行并排蛋白粉和搜索／手动入口，再展示各餐。蛋白粉一份即可记录，旁边“…”可调整份量，保存后可撤销；入口沿用当前所选日期。窄屏或大字体空间不足时，下方操作纵向排列，保留完整文字和点击区域。
- 进度页回答"我离目标还有多远"：体重趋势在最上面。
- 方案选择回答"哪个适合我"：一张推荐卡，其余并排对比。
- 不重复展示同一信息；数据"今天没有行动意义"就不显示（没记过饮食的人不会看到蛋白条）。

## 2. 颜色：主色要省着用

- **主色（火焰橙 `#FF6A13`）只用于**：每屏最多一个大按钮、当前选中项、训练进度、真正可点的小字链接。数值一律用文字色或次要色。
- **语义色**：训练 = 主色，蛋白 = 金黄，热量 = 青蓝，坚持/完成 = 绿。
- 超过目标**不用红或琥珀**，用"第二圈"和中性文字；红色只用于错误、危险操作、疼痛安全提示和更新小红点。
- 颜色全部来自 [`lib/theme/tokens.dart`](../lib/theme/tokens.dart)，界面代码里写死颜色会被 `tool/lint_tokens.sh` 拦下。

## 3. 措辞：不评判身体

- 不用"偏高 / 微胖 / 偏瘦"给人贴标签，说"你的起点"和"路线"（减脂 / 重组 / 微调 / 精修 / 增肌 / 成长期）。
- 不用"失败 / 偷懒 / 超标"；用"还差 38 g 蛋白""今天多吃了 120 千卡"这类陈述。
- 术语说人话："努力 8"→"吃力 8/10"或"还能做 2 次"。
- 估算类提示一句话、灰色小字，不用整块警示框。
- AI 结果展示估算依据与待确认信息，不把模型自评的高／中／低当作可信准确率。前后照片无法对应时降级到吃前估算，允许逐项调整食用量。
- 未成年（成长期）不出现热量缺口与减脂字样。

## 4. 动效

- 内容出现、消失、替换、展开都有 180–320 ms 的过渡（`Reveal` / `PushSwitcher` / `FadeSwitcher`），不允许"瞬间切换"和"高度突然跳变"。
- 所有动画可被打断；手势期间不重建整页；尊重系统的"减弱动态效果"。
- 点击反馈统一用 `Pressable`（按下缩到 0.97）。
- 触觉统一由 `AppHaptics` 管理并尊重触感开关：选择改变用刻度，开始／继续训练、热身完成及保存成功用轻震，动作首次完成用中震，当日训练首次达标用轻→中短双震，前台休息自然到点用轻→轻短双震。一次操作只播放最高一级；重复选择、数值到边界、自动翻页、营养达标不额外震。记录页训练｜饮食切换、手指翻周／翻月、日历展开收起吸附，以及引导页身高体重刻度尺每过一格，都用选择刻度（刻度尺经节流）。连续调数限制频率，后台不播放界面触感。

## 5. 版式

- 页面大标题 34/700；卡片标题 17/600；正文 15–17；说明 13；最小 12。
- 点击目标不小于 44×44；可点元素都有无障碍语义标签。
- 分组列表用 `GroupCard/GroupRow`：同组行放进一张圆角卡，行间缩进细线，值用次要色，可点行右侧箭头。
- 宽屏（折叠屏内屏、横屏）：左侧竖向导航条，内容区限制最大宽度并居中，必要时双栏。

## 6. 分享与品牌

字标"薄肌日课"（得意黑子集）只出现在今日页顶部、我的页底部和分享素材里，**不放大**——小而精比大字更高级。
