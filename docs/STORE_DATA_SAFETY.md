# 应用商店隐私/数据安全填写指引

这份文档帮你在上架 Google Play 和 Apple App Store 时，快速、准确地填写数据安全 / 隐私标签。所有事实与 [PRIVACY.md](../PRIVACY.md) 一致。**上架前请再对照最新代码确认一次。**

## 一句话事实

- 没有账号、没有服务器、没有广告、没有统计 SDK、没有崩溃上报 SDK。
- 用户数据（资料、训练、饮食、体重、照片）只存在设备本地；系统云备份已关闭。
- 唯一的网络行为：① 用户自己配置的"拍照识别"接口（用户主动触发，把一张饮食照片发给**用户填写的服务商**）；② 检查更新（只读版本号，不带任何标识）。
- API 密钥使用 Android Keystore 加密保存在本机，不进入备份文件。

## Google Play · 数据安全（Data safety）

| 问题 | 建议填写 |
| --- | --- |
| 应用是否收集或分享用户数据？ | **收集：否**；**分享：否** |
| 数据是否在传输中加密？ | 是（所有联网都强制 HTTPS） |
| 是否提供删除数据的方式？ | 是：卸载应用或在系统设置里清除应用数据；也可在应用内删除记录 |
| 是否有账号？ | 无 |
| 健康与健身数据 | 应用在设备上处理，**不收集** |
| 照片 | 仅在用户主动使用"拍照识别"时，由用户配置的第三方服务处理，应用本身不收集 |

> Google 的定义里，"仅在设备上处理、不发送出设备"的数据**不算收集**。拍照识别发送到的是用户自己填写的服务，应用开发者不接收，请在商店说明里写清楚这一点。

## Google Play · 应用内容分级与健康声明

- 应用类别：健康与健身。
- 需要在商店说明里加入免责声明：本应用提供的是一般性训练与饮食参考，**不是医疗建议**。
- 如果面向未成年人上架，请阅读 Play 的家庭政策；应用已为未满 18 岁用户提供"成长期"路线（无热量缺口），但**目标用户仍是成年人**。

## Apple App Store · 隐私营养标签（App Privacy）

| 项目 | 建议填写 |
| --- | --- |
| 数据收集 | **不收集数据**（Data Not Collected） |
| 追踪 | 否 |
| 隐私政策网址 | 填你的 `privacyPolicyUrl`（见 `lib/config/app_links.dart`） |

> 说明：目前只有 Android 版本。若将来做 iOS 版，需要重新核对原生层的权限与说明（相机、通知），并保持以上事实不变。

## 权限清单（Android）

| 权限 | 用途 | 上架时的说明文案建议 |
| --- | --- | --- |
| `INTERNET` | 拍照识别（用户配置）、检查更新 | "仅用于你主动使用的拍照识别和检查更新" |
| `POST_NOTIFICATIONS` | 训练提醒、休息提醒 | "按你设定的时间提醒训练" |
| `SCHEDULE_EXACT_ALARM` | 准点提醒 | "让训练提醒在设定时间准点出现" |
| `RECEIVE_BOOT_COMPLETED` | 重启后恢复提醒 | "手机重启后自动恢复提醒" |
| `CAMERA` | 拍饮食照片 | "拍摄你的饮食照片，仅在你点击拍照时使用" |

`SCHEDULE_EXACT_ALARM` 在新版 Android 上需要用户授权，Google Play 对该权限有用途审核，需要说明"日程/提醒类功能"。

## 上架前检查清单

- [ ] `lib/config/app_links.dart` 三个链接已填写；
- [ ] 隐私政策页面可公开访问，内容与 App 内一致；
- [ ] `PRIVACY.md` / `assets/legal/privacy.md` 末尾的联系方式已填写；
- [ ] 商店说明里有"不是医疗建议"的免责声明；
- [ ] 食物库为估算值的说明（App 内已有，商店说明里也建议写一句）；
- [ ] 发布包已用自己的签名构建，并通过 `tool/check_apk.py`。
